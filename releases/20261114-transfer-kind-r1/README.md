# «Перевод»: по ссылке или на карту Анне, r1 · 14 ноября 2026

Решение владельца 14.11.2026. Копии `20261114-group-blocks-r1` (байты Git) с правками:
под-выбор `#transfer-clarify` в доке рядом с «Как оплатили» (тот же блок `k-dock__sub self-clarify`, те же кнопки
`self-sub-btn`, без новых цветов), подсказка на кнопке «Выберите, куда перевели», в журнале и в чеке
«Перевод · по ссылке» / «Перевод · на карту Анне». Константа `BLOCK_CAPTIONS` и сетка — как в group-blocks-r1.

Встроенный код трёх HTML: состояние `transferKind` ('link' | 'card'), спрашивается только у «Перевод»; без выбора чек
не закрывается (и с картой клиента); другой вид оплаты сбрасывает выбор, поле не отправляется. Чек уходит на сервер
полем `transferKind` (в офлайн-очереди — вместе с чеком); правка чека показывает сохранённый вариант и позволяет сменить.
«Смешанная», «Себе оплачено», цены, акции, бонусы, PIN, очереди, service worker, хранилище, итоги не менялись.
Черновик после перезагрузки страницы выбор не хранит: продавец выбирает заново (кнопка закрытия подскажет).

Сервер: `cashier-transfer-kind-20261114` (поле хранится в `retail_checks.raw_row_json.omotiTransferKind`, без миграции).
Касса работает и с сервером до выпуска: поле там просто не сохраняется.
QA: `_qa/transfer-kind/transfer-kind.cjs` (перехваченный транспорт, настоящий код сервера на PostgreSQL в памяти).
