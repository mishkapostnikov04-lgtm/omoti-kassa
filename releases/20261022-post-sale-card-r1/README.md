# Добавление карты к оплаченному чеку · 22 октября 2026

Три кассы. Журнал → обычный оплаченный чек → Редактировать → Добавить бонусную карту.

Отдельный режим использует сохранённый чек и подтверждает начисление. Состав, скидки, оплата и дата сохраняются. Списать бонусы задним числом нельзя. Изменённые, ещё не сохранённые позиции требуют явного отказа от этих изменений перед добавлением карты.

Уже бонусный чек по-прежнему открывается в прежнем редакторе с заменой карты. Брак, служебные операции, Яндекс и неподтверждённые чеки не получают действие добавления. Существующие API и ключи pending/черновиков сохранены. Новая identity хранит полный замороженный запрос; пассивная сверка не создаёт финансовую отправку, явная проверка статуса может повторить только тот же запрос. Не очищать хранилище и не создавать второй чек при неизвестном результате.

Требуется совместимый серверный выпуск `cashier-post-sale-card-20261022-r1`. Он регистрирует бонусную покупку для уже существующей продажи и меняет только её бонусную метаинформацию. Никакой второй кассовой продажи, повторного расхода моти/набора и повторного начисления сотруднику. SQL-защита допускает только узкий переход метаданных и сохраняет прежнюю защиту проведения/правок.

Старые ресурсы, сервис-воркеры, сканер, основной координатор новых бонусных продаж и финансовые формулы сохранены. Стили используют действующие компоненты C3.2. Обновление открытых касс не принуждается.

Проверка: `_qa/post-sale-card/regression.cjs` (QA_POINT, QA_OUT, QA_PUBLIC_BASE). Все бизнес-запросы mock, SW blocked; реальные чеки/бонусы/устройства/заявки запрещены. Физический iPhone этим не проверяется. Серверные фикстуры, PG-проверка, манифесты и handoff — в `/opt/omoti/releases/cashier-post-sale-card-20261022-r1`.
