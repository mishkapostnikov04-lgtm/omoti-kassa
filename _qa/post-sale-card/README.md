# Проверка добавления карты после продажи

`node _qa/post-sale-card/regression.cjs` — 8 сценариев каждой из 3 точек: просмотр и отмена без записи, одно добавление и следующая продажа, unknown/reload/status без повторной отправки, восстановление введённого номера, ошибка расчёта/повтор, недоступность для брака, отмена подтверждения, отказ хранилища до отправки.

QA_POINT ограничивает точку. QA_OUT задаёт отдельную папку результатов. QA_PUBLIC_BASE=https://mishkapostnikov04-lgtm.github.io/omoti-kassa/ проверяет опубликованные статические файлы. Все business/provider запросы перехватываются; service worker blocked. Не регистрировать реальные устройства и не создавать тестовые финансовые операции в production. Существующий shift/editor/restock harness остаётся без изменений.

Браузерная эмуляция 390×844 не заменяет физический iPhone Safari/PWA. Нельзя заявлять проверку реального телефона или полной смены на основании этих фикстур.
