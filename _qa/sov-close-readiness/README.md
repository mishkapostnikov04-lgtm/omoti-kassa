# Советская: неясная блокировка после ввода карты · 21.10.2026

Продолжение от21.10: `regression.cjs`, `audit.cjs`, `startup.cjs` принимают `QA_POINT=anikina|novogodnyaya|sovetskaya` (по умолчанию Советская). При расширении на все точки сохраняются запоминание продавца Аникиной, PIN Советской и отдельные ключи хранилища. Audit проверяет также принадлежность диагностики точке и фокус после отложенных UI callbacks. Для каждого запуска указывать новую `QA_OUT`, чтобы не перезаписывать историю.

Текущий выпуск: `releases/20261021-cashier-readiness-r1/README.md`. Все бизнес-запросы остаются mock и при `QA_PUBLIC_BASE`. Результаты переноса: `../../../_local_artifacts/cashier-readiness-rollout-20261021/`. Редактор и feedback runners теперь также принимают `QA_OUT`.

`regression.cjs`: 13 сценариев на синтетических данных: введённый/ошибочный номер, отдельные read и submit, ошибки карты/расчёта, медленный ответ, отмена read, два timeout, unconfirmed первая покупка, restart draft, неизвестный финансовый intent, отсутствующий продавец, 360/390px и синтетические 10 моти + мункейк / 2420 ₽. Таймер read timeout в одном сценарии ускорен; финансовые таймеры не меняются.

`startup.cjs`: 5 ошибок обязательных ресурсов с восстановлением, discarded retained edit и сохранение настоящего pending identity. URL берётся из фактического manifest. Запускать с QA_POINT=sovetskaya.

`audit.cjs`: 22 сценария дополнительного аудита. Deadline включает тело HTTP-ответа; неполный JSON и HTML вместо ответа; неверное списание; исходный ошибочный ввод после reload; конфликт акции; поздние ответы карты/корзины; потеря доступа; фон/возврат; двойное нажатие; отказ localStorage; потеря подтверждения checkout; unknown/status; отключённое проведение бонусов; смешанная оплата; ограниченная диагностика без карт и содержимого чеков. QA_ENGINE=webkit запускает тот же набор в Playwright WebKit, что не заменяет физический iPhone.

QA_OUT задаёт отдельную папку результатов этих трёх runner. QA_PUBLIC_BASE=https://mishkapostnikov04-lgtm.github.io/omoti-kassa/ проверяет опубликованную статику, сохраняя mock всех business API. Дополнительно: `_qa/anikina-freeze/shift.cjs` (9), `restock.cjs` (5), `restock-draft.cjs` (10), QA_POINT=sovetskaya, QA_OUTPUT=папка результатов. Исторический shift runner обновлён под существующий редактор от21.10: «Изменить состав и оплату» и C31Confirm.

Существующий `_qa/card-edit-camera/frontend-regression.cjs`: ещё 7 сценариев редактора/полного номера/сканера/PIN/продавца. Выход этого исторического runner копируется в новую task папку.

`probe.cjs` — RED-доказательство прежнего baseline b9cbbc3, запускается на старом ресурсе (или опубликованной старой версии с QA_PUBLIC_BASE). Он намеренно требует старую неисправность, не является PASS-тестом нового кода.

Все business/provider запросы перехвачены harness; SW blocked, real operations forbidden. Артефакты: `../../../_local_artifacts/sovetskaya-close-block-20261021/`. Номер настоящей карты и состав полученной от владельца покупки хранятся только там в PRIVATE_*; не переносить в тесты, Git и обычные отчёты. Physical Safari/PWA и точный триггер на устройстве продавца этими проверками не доказаны.
